# 쇼핑몰 규칙 관리자 — 사용법 매뉴얼

**버전 v0.7.0 기준** | 단독 실행형 관리자 프로그램 (ADMIN_SATAD_ALONE.MD)

쇼핑몰 캡처(HTML/MHTML)에서 품목을 추출하는 **파싱 규칙**을 만들고, 검증하고,
배포까지 하는 관리자 전용 프로그램입니다. 사용자용 "자동 품의 요구 생성기"와 **동시에
실행해도 충돌하지 않습니다**(이름·저장소·포트가 모두 분리).

---

## 1. 시작하기

### 1.1 사전 준비

| 준비물 | 용도 | 필수 여부 |
|---|---|---|
| 대상 저장소 폴더 | `rules.json`과 `.git`이 있는 자동품의요구생성기 저장소 | 필수 |
| OpenCode | AI 규칙 생성(Z.ai GLM Coding Plan) | AI 생성 시 필수 |
| Z.ai Coding Plan 등록 | `opencode auth login`으로 인증 | AI 생성 시 필수 |
| TYPESAFE_API_KEY | Jev 의미 판정 게이트 | 선택(없으면 관리자 검토로 동작) |

- OpenCode 미설치 시: AI 생성 대신 **클릭 매핑**으로 규칙을 만들 수 있습니다.
- TYPESAFE_API_KEY 저장: Jev 패널의 Key 입력란에 붙여넣고 **[💾 저장(safeStorage)]** —
  Windows 암호화(safeStorage)로 저장되며 평문으로 기록되지 않습니다.

### 1.2 실행과 저장소 열기

1. `ShoppingMallRuleManager-Portable.exe` 실행 (또는 개발: `npm run dev`)
2. 프로그램이 저장소를 자동 탐지합니다 — exe는 압축 해제 폴더에서 실행되기 때문에
   **첫 실행에는 [폴더 선택…]로 저장소 루트를 한 번 지정**해야 하며, 이후 실행에는
   **마지막 저장소가 자동으로 다시 열립니다**.
3. 상단에 **경로 · 규칙 N개 · rules.json 버전 · Git 연결** 상태가 표시되면 준비 완료.

> 명령줄로 바로 열기: `ShoppingMallRuleManager-Portable.exe --project=C:\저장소경로`

## 2. 규칙 편집·삭제

### 2.1 편집

1. 규칙 목록에서 **[편집]** 클릭
2. JSON을 수정 — 문법 오류는 저장 시 검증되어 위험한 내용이 저장되지 않습니다
3. **[🔍 변경 전후 비교]**로 +n/−n 줄 diff 확인
4. **[💾 저장]** — 소스 규칙과 analysis 사본 두 곳에 한 번에 저장되며,
   저장 전 **스냅샷이 자동 백업**됩니다(실패 시 자동 복구)

> 목록 상단의 **검색창**(ID·이름)과 **종류 필터**(전체/장바구니만/주문서만)로
> 32개 규칙을 빠르게 찾을 수 있습니다.

### 2.2 삭제 (2단계 확인)

1. **[삭제]** 클릭 → 삭제 대상 파일 목록 확인
2. **규칙 ID를 직접 입력**해서 확인 (오탈자 방지)
3. 삭제 후 rules.json이 자동 재반영됩니다. 문제가 생기면 백업/복원 화면에서 되돌리기 가능.

> 삭제한 규칙이 사용자에게 전파되려면 **새 exe 배포**가 필요합니다(rules.json 갱신만으로는
> builtin 규칙이 사라지지 않습니다).

### 2.3 builtin 등록 · rules.json 재생성

- **[🧩 builtin 등록]** — 파일로만 있는 규칙을 프로그램 내장 목록에 추가합니다.
  새 exe에 포함되어야 할 규칙만 등록하세요.
- **[📥 rules.json 재생성]** — 소스 규칙 전체로 배포용 rules.json을 다시 만듭니다.
  버전은 Git 배포 시 1씩 올라갑니다.

## 3. 새 규칙 만들기 (AI 자동 생성)

### 3.1 준비물 — 캡처 폴더 구성 (권장 방식)

배송비는 구매 금액에 따라 무료이기도 하고 발생하기도 하므로, **두 상황의 캡처를 모두**
준비하면 규칙 정확도가 올라갑니다. 폴더를 이렇게 구성하세요:

```
무신사\                       ← 쇼핑몰 이름 폴더 (이 폴더 하나만 지정)
  배송비무료\
    장바구니.html  장바구니.mhtml
    주문서.mhtml
    정답_품목.xlsx             ← 그 캡처 시점의 정답
  배송비발생\
    장바구니 2.mhtml
    주문서2.mhtml
    정답2.xlsx
```

- **[📂 폴더 불러오기]** 한 번이면 끝 — 프로그램이 하위 폴더까지 훑어
  - 파일명·폴더명의 **"장바구니/주문서"**로 화면 종류를 분류하고
  - **"무료/유료(배송비)"**로 배송비 상태를 태그하며
  - 같은 폴더의 **정답 Excel을 캡처별로 자동 매칭**합니다 (html+mhtml 중복은 mhtml 우선 1개만)
- **캡처가 있는 화면 종류는 생성 대상 체크박스가 자동으로 켜집니다** —
  주문서·장바구니 폴더가 섞여 있어도 한쪽이 빠지지 않습니다.
  (html+mhtml 쌍은 같은 문서이므로 mhtml 1개로 병합되며, 병합 수는 요약에 표시됩니다)
- 캡처가 많아도 됩니다(종류당 최대 20개). **AI 프롬프트에는 배송비 무료 1 + 발생 1 대표
  샘플**만 들어가고, **검증은 전부 수행**해 정확도를 높입니다.
- 파일을 직접 고르고 싶으면 기존 **[파일 직접 선택]**도 그대로 사용할 수 있습니다.

### 3.2 진행

1. **[🤖 새 규칙 만들기]** 클릭
2. 쇼핑몰 이름 입력 → **기본 ID 자동 파생** (주문서: `id`, 장바구니: `id-cart`)
3. 생성 대상 선택(주문서/장바구니)
4. **[📂 폴더 불러오기]**로 캡처 폴더 지정 (또는 종류별 파일 직접 선택)
5. 정답 Excel 확인(폴더에서 자동으로 가져온 것 중 하나) + 정답 기준 화면 선택
   - 캡처별 정답이 붙은 샘플은 **각자 자기 정답과 대조**됩니다
   - 정답이 어느 화면 기준인지 모르면 "공통/알 수 없음" (0건 여부만 판정)
6. **[▶ 생성 실행]** — 진행 로그 실시간 표시
7. 완료 후 결과 확인(캡처별 대조 ✓/✗ 포함) → **[📥 프로젝트에 적용]**

### 3.3 결과 해석

| 상태 | 의미 |
|---|---|
| **approved** | 로컬 검증(건수·총액 일치) + Jev 의미 판정 통과 — 적용 권장 |
| **repaired** | 1차 후보가 실패해 AI가 수정한 뒤 정답과 일치 — 내용 확인 후 적용 |
| human_review | 자동 판정 실패 — 결과를 직접 확인하거나 폐기 |
| reject | 구조가 부적합해 폐기 — 샘플·정답을 확인하고 재시도 |

- AI는 **후보 3개**를 만들고 각각 로컬 검증 + Jev 판정을 거칩니다.
- 1차 실패 시 **최대 3회까지 스스로 수정**하며, 같은 답을 반복하면 중단합니다.
- Jev(TYPESAFE_API_KEY)가 없거나 오류가 나면 자동 배포하지 않고 **관리자 검토**로 보냅니다
  — 초안은 사라지지 않습니다.

### 3.4 적용 옵션

- **rules.json 재생성**(기본 켜짐) · builtin 등록 · Git 커밋/push는 체크 시에만 실행됩니다.
- 적용 전 **기존 규칙 대비 diff**를 확인할 수 있습니다.

## 4. 클릭 매핑 (AI 없이 규칙 만들기)

1. **[🖱 클릭 매핑]** → 샘플 HTML/MHTML 열기
2. 좌측 뷰어에서 요소를 클릭해 8단계를 진행합니다
   (① 상품 행 → ② 상품명 → ③ 수량 → ④ 단가 → ⑤ 배송비 → ⑥ 체크박스 → ⑦ 옵션 행 → ⑧ 확인)
   - 단계 이름을 클릭하면 그 단계로 이동하고, **[클릭 모드]** 버튼으로 다시 지정합니다.
   - 건너뛰어도 되는 단계: 수량(기본 1), 배송비(없음), 옵션 행
   - **장바구니 규칙은 ⑥ 체크박스 선택이 필수**입니다.
3. 상품이 여러 개면 같은 종류 요소를 2개 이상 클릭하세요 — 공통 선택자가 자동 도출됩니다.
4. 우측에서 규칙 ID·이름·match(도메인)를 입력 → **[🧩 규칙 조립]** → **[👁 추출 미리보기]**로
   실제 추출을 확인 → **[💾 저장]**

## 5. 검증 센터

### 5.1 전체 검증 (§7.7)

**[▶ 전체 검증 실행]** 한 번으로 다음을 등급별(ERROR/WARNING/INFO/PASS) 보고합니다.

- JSON 문법 · 스키마 · ID 중복 · 파일명-불일치
- 장바구니 checkedOnly 누락 (예외 몰은 설정으로 WARNING 강등)
- match 중복 · bundle(rules.json) 동기화 · 버전 형식 · **-cart 우선순위**

**ERROR가 하나라도 있으면 적용·배포를 보류**하고 원인을 표시합니다.

### 5.2 샘플 추출 검증

1. **§7.7 샘플 추출** 탭 → **[캡처 폴더 선택…]** (하위 폴더까지 최대 60개 검사)
2. 각 캡처를 규칙으로 실제 추출해 같은 폴더의 정답 Excel과 **건수·총액(2% 이내)** 대조
3. 판정: 0건·불일치 = ERROR, 정답 없음/미지원 몰 = INFO

### 5.3 규칙 비교 (§7.4)

두 규칙을 선택하면 라인 단위 diff로 차이를 보여줍니다.

## 6. 백업/복원 (트랜잭션)

- 규칙 **저장·삭제·생성 적용**은 모두 트랜잭션으로 처리됩니다 — 적용 전 자동 스냅샷,
  실패 시 자동 복구, 이력은 `transactions/` 폴더에 남습니다.
- 백업/복원 화면에서 이력의 **[↩ 되돌리기]**를 누르면 해당 시점으로 복원됩니다
  (신규 생성분은 삭제, 수정분은 원본 복원). 이미 되돌린 이력은 재되돌리기 할 수 없습니다.

## 7. 배포/Git

1. 변경 파일 목록에서 **배포할 파일만 체크** (`git add .`는 금지 — 서비스가 인자 자체를 거부)
2. **[🔍 선택 diff 보기]**로 내용 확인
3. 커밋 메시지 입력(예: `feat: 무신사 쇼핑몰 규칙 추가 및 rules.json 갱신`) → **[Commit]**
4. **[Push]**는 별도 버튼 — 실패해도 **로컬 커밋은 보존**되며 실패 사유가 표시됩니다
5. 강제 push는 할 수 없습니다.

## 8. 작업 로그 (§7.9)와 AI 연동 상태

- **하단 상태바**: 항상 마지막 작업 상태와 **오류/경고 수**가 표시됩니다.
  **[📋 로그]**를 누르면 전체 작업 로그 패널이 열립니다 — 레벨 필터(오류/경고/정보),
  클립보드 복사, 파일 저장(.txt)을 지원하며 API Key 등 민감정보는 자동 마스킹됩니다.
- **OpenCode 브리지**: 설치 여부·버전·사용 가능한 GLM Coding Plan 모델 목록 표시.
  "인증: 미등록"이면 터미널에서 `opencode auth login`으로 Z.AI Coding Plan을 등록하세요.
- **Jev 판정 게이트**: Shadow Mode 통계(기록/비교/일치율)가 표시됩니다.
  - **[🧾 §19.2 픽스처 수집]** — 72개 테스트 케이스를 Jev로 판정해 통계를 쌓습니다.
  - **자동 승인**은 비교 데이터 50건 이상 + 일치율 충족 + Shadow Mode 해제 전까지
    설정 자체가 잠겨 있습니다(안전 설계).

## 10. 보안 원칙

- API Key는 **safeStorage 암호화** 또는 환경변수로만 저장 — 코드·로그·Git에 기록되지 않습니다.
- Jev에는 전체 HTML이 아닌 **요약 데이터**(선택자·상품명 일부·개수)만 전송됩니다.
- 샘플 뷰어는 스크립트를 전부 제거하고 외부 네트워크를 차단합니다.
- 로컬 검증(건수·금액)을 통과하지 못한 규칙은 Jev 결과와 무관하게 배포가 차단됩니다.
